# Contributing to Greyfoundry projects

Thank you for helping improve Greyfoundry projects.

Repository-specific contribution instructions take precedence over this default. Read the repository's README, contribution guide, architecture documents, security policy, and license before starting work.

## Before opening a pull request

- Search existing issues and pull requests.
- Open or join an issue before investing in a large, cross-cutting, or compatibility-sensitive change.
- Keep changes focused and preserve unrelated behavior.
- Add or update tests for production behavior.
- Update documentation when behavior, configuration, compatibility, or operational requirements change.
- Follow the repository's licensing, provenance, generated-file, and source-header rules.
- Never include credentials, private data, hidden planning material, or unrelated logs.

## Pull requests

Explain the problem, the chosen approach, important trade-offs, and how the change was verified. Link the relevant issue when one exists.

Maintainers may request changes, split a proposal, decline work outside the project's scope, or ask for additional evidence before merging.

## Security

Do not report vulnerabilities through a public issue or pull request. Follow the repository's SECURITY.md or the Greyfoundry default security policy.
